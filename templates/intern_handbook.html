角色与租户边界

普通投资者只访问所属租户内容；研究型大V管理自身租户；Admin 是平台治理角色，不能被大V替代访问。所有测试必须同时记录角色和租户。

共享业务链路

内容录入与互动先按租户保存，再形成知识、标签、记忆和关系；Hermes 与复盘优先使用这条沉淀链路输出可追溯的研究结果。

LEARNING FLOW

建议学习路径

按阶段推进，不绑定学习天数。每阶段完成后再进入下一阶段，可根据已有经验合并或重复任一阶段。

阶段目标：能说清“谁在什么入口、看什么数据、能做什么”。
  • 从系统地图进入 H5、大V工作台与 Admin，比较三个角色可见菜单。
  • 理解“租户”是内容、知识、互动和数据隔离边界，不是单纯展示筛选条件。
  • 确认市场与指标请求必须展示真实来源，数据不可用时不得以模拟内容替代。
阶段目标：能独立完成一条普通用户与一条大V核心业务链路。
  • 普通用户：注册、合规确认、渠道选择、自选股搜索、详情、评论、复盘阅读和消息。
  • 大V：创建复盘、编辑用户输入、选择或不选择自选股、确认发布并在前台查看。
  • 录入一条知识，确认大V看到的是可阅读词条和知识分层，而不是治理字段。
阶段目标：理解每次 AI 结果为何可信或为何需要提示缺失。
  • 区分个股、指数/指标图表、知识问答、报告/URL 解读、复盘证据链和产品帮助意图。
  • 查看 Hermes 新会话、历史会话续问与长期记忆如何按租户沉淀。
  • 对“只要图”和“图加解读”分别体验，检查图表类型、数据来源和解释是否匹配。
阶段目标：理解平台配置如何真实影响前台，而不是只改变页面文案。
  • 查看 Admin 的角色权限、功能开关、模型映射、知识与记忆治理、数据湖和访问审计。
  • 理解 Admin 页面/API 仅 admin 可访问；数据库写操作额外需要独立二次口令。
  • 用 Excel 测试用例按角色筛选，选择对应模块开展覆盖性验证。

WORKING PRINCIPLES

学习与测试中的判断原则

先问数据从哪里来

市场数据、指标和图表要检查来源、更新时间、代码与空态。真实数据不可用时，正确行为是解释限制，而不是给出模拟结论。

再问属于哪个租户

复盘、知识、消息、评论、记忆和经营统计都必须带租户边界。角色正确但租户错误，仍是严重问题。

最后问配置是否真正生效

功能开关、访问策略和模型映射不仅影响菜单，也必须约束对应页面与接口行为；不能只做到视觉隐藏。
