ARCHITECTURE AUDIT · 2026-09-15 · READ-ONLY REVIEW

洞见智研架构、数据与跨端一致性分析报告

审计对象：H5、大V Web、Web、Admin、5051 数据迁移工具、PostgreSQL、定时任务与 AI 编排层
审计方法：代码静态扫描、路由清单、迁移文件、模板 API 调用、Domain Service 调用链、现有测试结果
总体结论：当前系统已经具备“大V洞见生产 + 粉丝消费 + 订阅商业化”的产品骨架，但仍处于工程收敛期。市场指标域已强制使用 AKShare 快照，5051 已成为唯一数据库发布控制面，运行时建表已清除；本次日志证明代码与目标数据库结构发生了真实漂移：应用查询已读取 user_watchlist_items.user_id，数据库尚未完成 115 迁移，导致 H5 直接返回 500。当前工程审计综合评分下调为 5.1 / 10。这个分数不是用户价值评分，也不是压测结果，而是对当前工程状态的风险调整评分。

七、架构设计判断

合理且应保留

  • 以 PostgreSQL 保存用户、租户、草稿、评论、标注和任务记录。
  • 页面层通过 API 访问 Domain Service，而不是直接拼接数据库逻辑。
  • AKShare 快照由定时任务统一刷新，H5 只读缓存。
  • 洞见形成“智能体回答 → 数据库草稿 → 编辑 → 发布 → 订阅权益”的主链路。
  • Admin 使用功能开关控制封存能力。

必须继续收敛

  • 保持市场指标域 AKShare 与个股研究域 Gangtise 的显式边界，禁止来源旁路。
  • 保持 5051 为唯一数据库发布控制面，主应用只提供业务 API。
  • 禁止业务请求承担 DDL 和迁移补救，执行 115 迁移并做孤儿数据审计。
  • 把 Hermes 自定义技能从 localStorage 迁移到数据库并加入版本控制。
  • 拆分过大的 core_services 和 market_services，按领域边界组织。

八、发布前必须完成的门禁

门禁未通过时的后果通过标准
数据源门禁同一指标不同页面显示不同值，用户无法判断可信来源。AKShare provider 断言、快照时间、任务运行记录三者一致。
数据库门禁生产可能因缺表、缺列、缺触发器而在运行时失败；本次已出现 H5 500。代码要求的 schema 与 schema_migrations 一致；115 已执行；新库初始化、升级库迁移、回滚库恢复和 H5 smoke 全部通过。
跨端门禁H5 看得到的能力，Web 或 Admin 可能使用另一套逻辑。同一功能 API、Domain Service、数据表映射唯一。
任务门禁重复调度造成重复扣费、重复写入或任务长期排队。唯一任务锁、幂等键、失败重试和停止状态测试通过。
性能门禁100 人同时访问时页面卡顿、数据库连接耗尽。100 并发压测达到 P95/API 错误率/连接池目标。
